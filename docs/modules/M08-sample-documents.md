# M08 — Synthetic sample documents

**Status:** Done

## Goal
A realistic, fully fictional document set in `samples/` with deliberate, known discrepancies. A reviewer can demo the app in about a minute and see every output type: comparison table, discrepancies, missing information, key-value facts and summary.

## Scenario
Business loan application for a fictional company, **Nimbus Agro Foods Pvt Ltd**. Identifiers are obviously fake (`FSL-TEST-0042`, `+91-00000-00000`, example.com).

## Deliverables
- [x] `samples/application_form.pdf`: generated by `scripts/generate-samples.ts` with pdfkit. The generator is committed with the output.
- [x] `samples/supporting_letter.txt`: name, address, licence expiry and revenue variants, plus an existing EMI obligation.
- [x] `samples/financials_fy2025.csv`: long-form table (`metric`, `fy2024`, `fy2025`). Indian digit grouping is quoted.
- [x] `samples/kyc_summary.txt`: company-name formatting variant, co-director missing, no revenue.
- [x] `samples/invalid_samples/`: `fake.pdf`, `empty.txt`, `script.exe`, `notes.docx`. All are rejected.
- [x] `samples/EXPECTED_FINDINGS.md`: every planted item, the files involved, mock detection status, and a manual checklist.
- [x] `samples/README.md`: file list, how to regenerate and seed, and how the automated check works.
- [x] `npm run samples:generate` (idempotent).
- [x] `npm run seed`: loads the four valid samples through the real validation, repository, buffer and processor services. It skips any sample already in the database.

## Acceptance
- Analysis with the instruction "Highlight discrepancies in names, addresses, licence details, or revenue figures" over the four valid files produces the four planted discrepancies and no false discrepancy for the company name. It also reports the co-director and KYC revenue as missing. Covered by `server/src/analysis/samples.test.ts`.
- Each invalid file is rejected with a specific code and reason.
- No real names, addresses or company data.

## Mock heuristics added for this set
The MOCK provider compared keys literally, so the planted items were missed. These changes are in `server/src/llm/mockExtraction.ts` and `mockAnalysis.ts`, with tests in `mockHeuristics.test.ts`:
- **Canonical keys.** Filler words (`annual`, `registered`, `trade`, `no`, `name`, and similar) are dropped, so `Annual Revenue FY2025`, `Revenue FY2025` and `Trade Licence No` compare equal. The period token is kept, so different years never merge.
- **Long-form CSV.** When the first column is a row label (`metric`, `item`, and similar), each period column becomes a composite fact (`revenue_fy2025`). The snippet is the whole row.
- **Company suffixes.** `Pvt`/`Ltd` and `Private`/`Limited` compare equal.
- **Indian digit grouping** (`4,80,00,000`) was already ignored by value comparison. It is now covered by a test.

## Known limits (see EXPECTED_FINDINGS.md, sections D and E)
- The mock does not compare dates with today, so it does not say the licence has probably expired.
- It does not read prose qualifiers ("provisional").
- It lists the EMI obligation as a fact, but does not summarise it as an obligation.
- (Changed after M10) Missing information is now computed in code for important fields only, so the list is short (about seven items on this set) and the same for the mock and a real model.
